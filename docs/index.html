UNA GUÍA PARA ENTENDER Y EMPEZAR

Una tienda propia,
sin empezar desde cero.

Go Store es un proyecto abierto para que un emprendimiento pueda ordenar su presencia en internet y empezar a recibir pedidos sin construir una web desde cero.

01 · VISIÓN

Que vender por internet sea más fácil de empezar.

Muchos emprendimientos muestran lo que ofrecen por WhatsApp o Telegram, pero no cuentan con una web ordenada que ayude a nuevos clientes a encontrar sus productos y realizar un pedido.

Go Store busca cubrir esa necesidad con un creador guiado, una tienda adaptable a teléfonos y computadoras y un panel sencillo para gestionar pedidos, sin exigir conocimientos de programación ni infraestructura.

La prioridad del proyectoUna experiencia clara y fácil de editar para quienes están empezando. El código es abierto y crear una tienda está pensado para ser gratuito.

02 · ESTADO ACTUAL

Un piloto funcional en construcción.

El recorrido implementado permite guardar y publicar una tienda, mostrar su catálogo y recibir pedidos básicos. El despliegue público todavía no está verificado.

01

Creador

Alta inicial con datos del emprendimiento, plantilla y primeros productos.

02

Tienda pública

Productos, búsqueda, categorías, carrito y envío de pedidos.

03

Editor independiente para actualizar marca, diseño, productos, precios y disponibilidad; también permite gestionar pedidos.

04

Cuenta

Inicio con Google o contraseña; la primera alta verifica el correo. Una tienda por cuenta.

03 · RECORRIDO

De la configuración a un pedido.

  1. Crear una cuenta. Se indica nombre, correo y teléfono; el primer acceso confirma el correo. Después se puede entrar con Google o contraseña.
  2. Completar la tienda. El creador guía la primera configuración del negocio, la plantilla y los productos iniciales.
  3. Administrar. El panel permite editar la identidad y apariencia de la tienda, gestionar productos, precios y disponibilidad desde una barra lateral.
  4. Publicar y recibir pedidos. La tienda se publica para clientes; el dueño consulta el pedido y cambia su estado desde la sección Pedidos.

04 · DESARROLLO LOCAL

Levantar la web en tu computadora.

El proyecto es estático y no necesita compilación. Servilo por HTTP para que funcionen el acceso por correo y las rutas; no abras los archivos como file://.

py -m http.server 8000

Luego abrí el creador local. La tienda pública usa /storefront/?slug=identificador; el panel para productos está en /admin/ y los pedidos en /admin/orders/.

RequisitosPython para servir los archivos y la CLI de Supabase para aplicar migraciones. Docker no hace falta para usar el proyecto hospedado.

05 · SUPABASE

Acceso, base de datos y pedidos.

Supabase mantiene usuarios, perfiles, tiendas, productos y pedidos. El frontend lee la URL y la clave publicable desde creator/supabase-config.js. Para configurar otra instancia, copiá el Project URL y la clave publishable (o anon, en proyectos que aún usan las claves anteriores) desde el panel de Supabase y reemplazá los valores de ese archivo. La clave publicable puede estar en el navegador; nunca pongas una clave secreta o service_role en el frontend.

Aplicar migraciones

Los archivos SQL están en supabase/migrations/. Con la CLI vinculada a la instancia:

supabase migration list --linked
supabase db push --linked
supabase migration list --linked

db push aplica migraciones pendientes. No uses supabase db reset --linked en la instancia con datos: reconstruye la base remota.

El pedido se crea mediante una función de Postgres que vuelve a validar tienda, disponibilidad y precios. Las políticas RLS limitan la lectura de pedidos al dueño.

06 · NETLIFY

Publicar los archivos web.

Netlify puede alojar las páginas estáticas; Supabase continúa siendo el backend. El archivo netlify.toml define estos valores:

Base directoryraíz del repositorio
Build commandprepara dist/ copiando las páginas
Publish directorydist

La configuración del repositorio construye dist/ con la portada, el creador, la tienda pública, el panel del negocio, ejemplos y esta documentación. Las rutas publicadas incluyen /creator/, /storefront/?slug=..., /admin/, /admin/orders/ y /docs/. Con GitHub conectado, Netlify puede desplegar cada push.

Despliegue pendiente de verificarEn Supabase configurá el Site URL de Netlify y permití los redirects de /creator/index.html y /admin/** para la verificación inicial y la recuperación de contraseña. El acceso con Google también requiere habilitar el proveedor y configurar sus credenciales en Supabase. Después del despliegue, confirmá las rutas del panel y la tienda.

07 · ARQUITECTURA Y PRIVACIDAD

Archivos estáticos y datos aislados por tienda.

creator/Alta inicial guiada de cada tienda.
storefront/Catálogo, carrito y envío del pedido.
admin/Editor autenticado de marca, apariencia y productos.
admin/orders/Consulta de pedidos y cambios de estado.
supabase/Esquema SQL, migraciones y políticas RLS.
docs/Guía breve para usar y desplegar el proyecto.

Una instancia de Go Store comparte una base de Supabase entre tiendas. El público consulta catálogos publicados; cada cuenta gestiona su propia tienda y sus pedidos.

08 · ALCANCE DEL PILOTO

Lo que todavía no incluye.

  • Pagos online ni confirmaciones automáticas por WhatsApp o correo.
  • Zonas o tarifas de entrega configurables; pago y entrega se coordinan directamente.
  • Dominio personalizado por tienda o onboarding público.
  • Despliegue comprobado en Netlify ni guía completa de instalación propia.

Publicar una tienda en Supabase hace visibles los datos seleccionados; el hosting web es un paso separado.

09 · INSTANCIA PROPIA

La guía de self-hosting se completará después.

El repositorio incluye migraciones para configurar una instancia propia de Supabase y publicar la web. La receta detallada se escribirá cuando el despliegue de referencia esté verificado y se pueda repetir desde cero.
